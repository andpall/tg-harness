# tg-harness — правила проекта

Telegram-бот, который передаёт сообщения в Claude Code (`claude -p`) и возвращает ответы.
Python 3.11+, ядро — только стандартная библиотека.

## Структура

```
src/tg_harness/
  __main__.py   точка входа, цикл getUpdates, запуск обработчиков в потоках
  config.py     .env (TG_TOKEN, TG_ALLOWED) + config.json → константы (TOKEN, ALLOWED, PROVIDERS, MODES, BUTTONS…)
  telegram.py   обёртки Bot API: tg, say, chunks, picker, typing, restart
  state.py      сессии чатов в памяти, блокировки на чат
  claude.py     один ход `claude -p` → (ответ, запрещённые инструменты)
  voice.py      голосовые → текст (faster-whisper, загружается лениво)
  handlers.py   команды, сообщения, inline-кнопки
tests/          pytest; conftest.py глушит Telegram и сбрасывает состояние
```

Новый код кладётся в модуль по смыслу. Не создавать `utils.py` / `shared.py` / `helpers.py` —
если код не подходит ни в один модуль, заведи новый с говорящим именем.

## Стиль

- Говорящие имена. Без однобуквенных переменных: `chat`, `session`, `provider`, `callback`, `error`.
- Ранний `return` вместо вложенных `if`. Не больше одного уровня вложенности условий.
- Команда бота = функция `cmd_<name>(chat_id, arg)` в `handlers.py` + строка в `COMMANDS`.
  Если команда выбирается inline-кнопкой — добавить её в `PICKER_COMMANDS`.
  Новая команда — ещё и в `set_commands()`, а если нужна кнопка на клавиатуре — в `config.BUTTONS`.
- Импортировать модули, а не имена: `from . import telegram` и `telegram.say(...)`,
  не `from .telegram import say`. Иначе тесты не смогут подменить функцию через monkeypatch.
- Комментарий — только «почему», когда это не видно из кода.
- Зависимости — только в `pyproject.toml`. Новую зависимость ради нескольких строк не добавлять.

## Тесты

- `python3 -m pytest` — обязательно перед завершением любой правки кода.
- Одна функция `test_*` на одно поведение; каждый тест стартует с чистым состоянием (фикстура `sent` в conftest).
- Сеть и настоящий `claude` в тестах не вызываются: Telegram глушит `sent`, `claude -p` — фикстура `fake_claude`.
- Нетривиальная логика (ветвление, разбор данных, права, перезапуск) — с тестом.

## Ограничения Telegram, о которые уже обжигались

- `callback_data` — не больше 64 байт. Имена провайдеров/моделей проверяются при старте в `config.py`.
- Сообщение — не больше 4096 символов: длинный текст резать через `telegram.chunks`.
- Перед `os.execv` в `restart()` обязательно подтвердить update (`getUpdates` с `offset`),
  иначе Telegram снова пришлёт `/restart` → бесконечный цикл перезапусков.
- Сбой `setMyCommands` и ошибки в цикле опроса не должны ронять процесс: иначе `run.sh` перезапускает его
  каждые 2 с и Telegram отвечает 429. В цикле после ошибки — пауза.

## Безопасность

- Каждое сообщение и каждый callback проверяется по `config.ALLOWED`.
- `arg` из callback приходит от пользователя — сверять с конфигом (`PROVIDERS`, `MODES`, список сессий), а не доверять.
- `TG_TOKEN` не передаётся в окружение `claude` (`env.pop` в `claude.py`).
- `.env` не коммитить. Список доступа (`TG_ALLOWED`) — тоже в `.env`, не в `config.json`. Секреты провайдеров — в `.env`, в `config.json` ссылаться на них как `"$VAR"`.

## Запуск

- `./run.sh start|stop|restart|log`. `run.sh` находит процесс по подстроке `-m tg_harness`, не по `python3`:
  Python из Homebrew на macOS перезапускает себя как `.../Python -m tg_harness`. Запускать только через `-m tg_harness`.
- После правки кода бота — `./run.sh restart` (или кнопка «♻️ Рестарт бота»).

## Если ты — Claude, запущенный этим ботом

При `"workdir": "."` ты работаешь в репозитории самого бота и правишь код, который тебя запускает.
Сломанный импорт или синтаксис = бот не поднимется и перестанет отвечать.
Перед тем как просить рестарт — прогони `python3 -m pytest`.
